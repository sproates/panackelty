An experimental programming language

Exact values.
Clear intent.

Small programs should be easy to write. Growing programs should remain easy to reason about. Panackelty brings exact numbers, checked domain types and explicit effects to a compact compiled language.

Write your first program → Explore the engineering

Developer preview 0.1.0-alpha.9 is available for Linux x86-64 and Apple silicon.

main(): Void {
  third = 1/3
  print((third * 30).nat())
  print((1/8).dec())
}
$ panack run exact.panack

10

Exact fractions, exact conversions. An unrepresentable exact conversion fails instead of silently rounding.

What you can use today

Small syntax.
Substantial semantics.

These capabilities describe the current source toolchain. For the downloadable preview’s exact contract, use the alpha.9 specification. Panackelty is ready for exploration and feedback; interfaces and compatibility are still evolving.

01 / Values

Numbers that stay exact

Arbitrary-precision Nat and Int, exact base-10 Dec and rational Rat values let you work without silently substituting floating-point approximations. Conversions make representability explicit.

Explore numeric semantics →
02 / Domain modelling

Rules belong with the type

Guarded types attach constraints to values: a positive count, a bounded port, a valid domain value. Records, enums, generics, Option and Result help describe both successful values and failure cases.

See a guarded type →
03 / Effects

Make side effects visible

A pure function cannot perform I/O or call effectful code. Keep calculations separate from interactions with the outside world, with the compiler enforcing that boundary.

Read the language rules →
04 / Everyday code

Collections and composition

Arrays, maps, sets, text and byte values support ordinary data processing. Pattern matching, loops, callable references, and library operations such as sorting let programs grow beyond arithmetic examples.

Explore collections →
05 / The host

Work with files and processes

Typed paths, filesystem and process APIs, structured errors, byte streams, output limits and timeouts support terminal tools. Exact durations and monotonic instants make elapsed-time calculations explicit.

Explore the host APIs →
06 / Development

Check, run, compile, test

The panack command checks source, runs programs, saves bytecode and disassembles it. Logical imports organise source; the testing library supports assertions, fixtures and captured command results.

Ideas you can run.

Works with alpha.9 and current source

A pure calculation, an effectful entry point

The greeting produces a value. main prints it. String interpolation keeps the result readable.


pure greeting(name: Str, answer: Nat): Str {
  "Hello, ${name}. The answer is ${answer}."
}

main(): Void {
  print(greeting("Ada", 42))
}

Output


Hello, Ada. The answer is 42.
Current source example

Give a business rule a name

Positive expresses a constraint on an integer. Code receiving this type can state its expectation directly.


type Positive = Int where value > 0

pure triple(n: Positive): Int {
  n * 3
}

main(): Void {
  answer: Positive = 14
  print(triple(answer))
}

Output


42

Under the hood

A language is more
than its syntax.

Panackelty brings together a compiler, a runtime and a body of verification work. Here is what those engineering milestones mean—and why they matter.

01

The compiler is written in Panackelty

A compiler translates a program into instructions the runtime can execute. Panackelty’s compiler is itself a Panackelty program: the language is substantial enough to implement its own language tooling.

Why it matters: self-hosting exercises real parsing, data structures, type checking and code generation together, far beyond a collection of demonstration programs.

Explore the compiler source →
02

It can rebuild itself reproducibly

A checked-in compiler seed starts the build. Successive compiler generations compile the compiler and standard-library conformance program; the bootstrap gate checks that the resulting artifacts match byte for byte.

Why it matters: the project tests a repeatable route from source back to its own toolchain. This is strong consistency evidence, not a mathematical proof that the compiler has no bugs.

Read the bootstrap evidence →
03

A complete pipeline, with one execution model

Source loading, parsing, name resolution, type and effect checks, bytecode emission, verification and execution form one toolchain. Source programs and saved bytecode both run on the C11 VM.

Why it matters: these parts must agree on the meaning of every operation. Bytecode is checked as untrusted input before execution.

Explore the architecture →
04

Guarantees reach below the surface

Exact numeric representations, checked domain values and explicit purity affect the compiler, bytecode and runtime—not just how code looks. The experimental async slice also coordinates suspension and typed completions across those layers.

Why it matters: useful language guarantees require consistent behaviour through the entire execution path, including error cases.

Inspect the specified behaviour →
05

Tests ask what happens when things go wrong

The project exercises malformed bytecode, allocation failures, runtime traps and cancellation, alongside compiler tests and complete programs. Sanitizers and Linux/macOS packaging checks add evidence beyond successful example output.

Why it matters: resource cleanup, rejection paths and distribution failures are part of building a dependable toolchain. Test coverage measures execution, not an absence of defects.

Where development is heading

A direction.
Not a list of promises.

The project separates working capabilities from investigations and longer-term ideas. There are no delivery dates implied here. The repository roadmap records the current decisions and priorities.

Working foundation

Build on what is proven

A self-hosted toolchain, verified bytecode, typed host APIs and a bounded async/await experiment provide a base for further work. The async experiment still uses fake host I/O.

Candidates for assessment

Make real work easier

  • Real TCP and timer integration, with careful cancellation and cleanup.
  • More useful compiler assistance and clearer development feedback.
  • Dependency-aware builds and a design for separate compilation.
  • Coverage measurement for Panackelty source itself.

These are candidates, not a committed implementation sequence.

Longer-term exploration

Broaden where it can go

Namespaces, richer libraries, interoperability and additional execution targets remain open areas. Browser, GUI, game and mobile applications are part of the ambition, not platforms supported by the current download.

Future investigation

Try it here, without installing anything

A browser playground could let visitors edit a complete example and run it, with output and compiler diagnostics alongside. A later REPL could retain definitions between inputs. Neither is available yet: browser execution, resource limits and session behaviour need investigation. Until then, the downloadable toolchain runs the examples above.

The vision

Useful enough to choose.
Clear enough to keep.

The ambition is a general-purpose language that developers and AI coding agents choose for real applications—and choose again when those applications need to change.

That means more than adding syntax. It means useful libraries, understandable errors, dependable behaviour, approachable installation and code that a person can read and maintain. Small terminal tools are a starting point; services, applications and other platforms are longer-term possibilities.

Panackelty aims to become a compelling alternative for work commonly done in Python or JavaScript/TypeScript. That is a goal to test, not a claim of superiority today. Early adoption experiments, real user feedback and measured engineering evidence should shape what comes next.

Your first program

From download
to “Hello, Ada.”

Start with developer preview 0.1.0-alpha.9. It includes the command, VM, compiler and standard library. Initial downloads support Linux x86-64 and macOS on Apple silicon; Windows is not part of this preview.

  1. Download and verify

    Get the archive for your platform and its matching .sha256 file from the release page. In your download directory, verify the checksum. It must report OK.

    Linux x86-64
    sha256sum -c panackelty-0.1.0-alpha.9-linux-x86_64.tar.gz.sha256
tar -xzf panackelty-0.1.0-alpha.9-linux-x86_64.tar.gz
    macOS Apple silicon
    shasum -a 256 -c panackelty-0.1.0-alpha.9-macos-arm64.tar.gz.sha256
tar -xzf panackelty-0.1.0-alpha.9-macos-arm64.tar.gz

  2. Save the greeting

    Copy the complete greeting example above into a file named hello.panack beside the extracted panackelty directory. Keep the extracted directory together: it contains the whole toolchain.

  3. Check it, then run it

    ./panackelty/bin/panack --version
./panackelty/bin/panack check hello.panack
./panackelty/bin/panack run hello.panack

    The version reports panack 0.1.0-alpha.9 (bytecode 8). The program prints Hello, Ada. The answer is 42.

  4. Save a compiled program

    ./panackelty/bin/panack compile hello.panack -o hello.bc
./panackelty/bin/panack run hello.bc

    You get the same greeting through saved bytecode. For a permanent installation or a build of the newer source, follow the full setup guide.
